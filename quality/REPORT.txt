BankHotel — результати завершальної перевірки
Дата: 26 листопада 2026 року
Перевірено локальні файли проєкту; ця редакція ще не відправлена в GitHub.

1. Внесені виправлення

• Внутрішні сторінки переведено на Mobile First: базові мобільні стилі, розширення через min-width.
• Додано спільне мобільне меню внутрішніх сторінок: кнопка, aria-expanded, закриття після переходу, натискання поза меню та Escape.
• Реалізовано змістовні сторінки «Про нас» і «Контакти» замість переходів на 404.
• Прибрано звичайні посилання на 404 і непрацюючу форму підписки; додано перехід до бронювання.
• Виправлено семантичні заголовки, підписи та початкові значення обов’язкових select; додано унікальні title, description і favicon.
• Винесено стилі сторінки 404 в окремий CSS, виправлено формат підключення шрифту й додано font-display: swap.
• Видалено непідключені застарілі CSS/JS та службову сторінку перевірки Supabase.
• Оптимізовано 25 фото: 52,2 MiB оригіналів → 7,3 MiB WebP-копій (приблизно на 86% менше). Це сумарна вага набору фото, не вага завантаження однієї сторінки.
• Імена фото в базі не змінювалися; статичні та динамічні сторінки використовують зіставлення з WebP. Оригінали збережено.
• CSS Sprite зберігає шість вихідних PNG без зміни байтів та три окремі векторні полігони. Стрілки слайдера залишаються зображенням.
• Supabase JS 2.119.2 підключено локально з MIT-ліцензією; завантаження інтерфейсу не залежить від CDN бібліотеки.
• Додано npm-команди збірки й тестів, файл фіксації залежностей та актуальну README.

4. Автоматичні перевірки

npm test — успішно, 8 тестових файлів:
• доступ до адмінського API, відсутність доступу гостя, помилки CRUD;
• дати/перетини бронювань, серверна ціна та користувач, повторна спроба й демооплата;
• закриття модальних вікон, захист від випадкового закриття під час запиту, відновлення після перезавантаження;
• EN↔UK на 16 сторінках, збереження мови, динамічні дані, незмінність адрес і значень форми;
• пошук, сортування, порожній каталог, нові/змінені/відсутні номери та помилки мережі;
• метадані, локальні ресурси й якорі, синтаксис CSS, клавіатурне керування меню;
• збереження оригіналів у спрайті, адреси вкладених сторінок і динамічні картки.

npm run test:security — успішно. Окрема локальна PostgreSQL (PGlite):
повторне застосування міграцій, RLS, CRUD адміністратора, заборона самопризначення
ролі, відкликання прав, зв’язок rooms/bookings, власник/ціна бронювання,
захист видалення номера зі збереженим бронюванням.

npm run test:server — успішно, 2 тести Express API.
Тести API використовують імітацію Supabase. Тести SQL використовують локальну базу.
Під час цієї перевірки робочі бронювання та користувачів у Supabase не змінювали.
Протокол: quality/automated-tests.txt.

npm run build — успішно.
npm audit у корені та npm --prefix server audit --omit=dev — 0 відомих вразливостей
на дату перевірки. Sharp оновлено до 0.35.5.
.env та node_modules виключені з Git; серед відстежуваних env-файлів — лише server/.env.example.
Клієнт містить publishable key. Серверні секрети не потрібно додавати до клієнта.

5. Браузерна перевірка

Браузер: Chromium у вбудованому браузері; це не замінює окремі перевірки Firefox/Safari.
Локальний сайт використовував опублікований API https://bankhotel-api.onrender.com.

Перевірено ширини 320, 390, 768, 1440 px для основних типів сторінок.
У перевірених станах горизонтального переповнення документа немає.
Порожня/гостьова адмінка, демооплата й 404 додатково перевірені на 320 px.
Після завантаження даних сторінку номера повторно оглянуто на 320 і 1440 px.

Перевірено через інтерфейс:
• відкриття мобільного меню та перехід на бронювання;
• збереження UK після переходу й перезавантаження, повернення до EN;
• отримання чотирьох номерів через реальний API;
• пошук із порожнім результатом, очищення пошуку, сортування за спаданням ціни;
• наступний слайд, назва/ціна/посилання номера;
• перехід гостя з бронювання на авторизацію;
• відмову в доступі до адмінки без входу.

Докази: quality/responsive-checks.json та quality/mobile-room.png.
Реєстрацію, вхід і CRUD з реальним адмінським акаунтом у цьому сеансі не повторювали;
їхню логіку перевірено автоматичними тестами, а користувачка підтверджувала роботу раніше.
Повну pixel-perfect звірку з Figma на кожному розмірі цей протокол не засвідчує.

6. Відповідність 14 вимогам на 10 балів

1 — Є понад 4 взаємопов’язані змістовні сторінки, окремо 404.
2 — Адаптивні базові стилі та min-width медіазапити (Mobile First).
3 — Мобільне меню на головній та внутрішніх сторінках.
4 — Слайдер номерів і розгортання послуг.
5 — Динамічні картки, форми та інтерфейс через DOM.
6 — Асинхронний API; стани завантаження, помилки, повторні спроби.
7 — Supabase для номерів, користувачів і бронювань.
8 — rooms і bookings пов’язані; зв’язок використовується в бронюванні та контролі видалення.
9 — CRUD номерів через інтерфейс.
10 — Реєстрація, вхід і вихід через Supabase Auth.
11 — Захищена адміністративна частина; одного входу недостатньо без ролі адміністратора.
12 — Перегляд, додавання, редагування й видалення номерів в адмінці.
13 — Пошук і сортування номерів за ціною.
14 — Серверна конфігурація через env; .env виключено з Git. Публічний publishable key не є серверним секретом.

Це оцінка реалізації та наявних перевірок, а не гарантія оцінки викладача.

   бронювання й CRUD під своїм адміністратором. Перевірити відсутність помилок у консолі.

4) Окремо пройти основні сценарії в Chrome, Firefox, Edge та Safari, бажано на реальному телефоні.
   Зафіксувати версії браузерів і скриншоти у звіті; ці чотири браузери тут не перевірялися окремо.
5) Виконати остаточну візуальну звірку з Figma та внести заплановані авторські правки.

Підключення бронювань BankHotel

1. У проєкті Supabase відкрий SQL Editor → New query.
2. Скопіюй весь текст 002_booking_creation.sql і натисни Run.
   Перший скрипт 001_initial.sql повторно запускати не потрібно.
3. Відкрий сайт через Live Server і онови сторінку (Ctrl+F5).
4. Увійди через Sign in у хедері головної. Після входу посилання зміниться на Account.
5. Вибери номер → Start booking → дати → At reception → Confirm booking.
6. Перевір запис у Supabase → Table Editor → bookings:
   user_id має відповідати ID твого користувача в Authentication → Users;
   room_id посилається на rooms; nightly_rate і total_amount розраховані базою.
7. Спробуй вибрати зайняті дати для того самого номера — їх не повинно бути у списку.
8. Для іншого вільного періоду перевір Online demo payment → Pay.
   До натискання Pay зберігається лише чернетка в цій вкладці браузера.
   Після Pay створюється бронювання; demo_paid = true, payment_status = pending.
   Реальних коштів немає, тому статус paid не встановлюється.

Технічні примітки
- Кожен запис rooms зараз означає один окремий номер, а не категорію з кількома номерами.
- Дати: наступні 30 ночей, часовий пояс Europe/Kyiv. Години заїзду/виїзду — фіксовані правила готелю.
- Запис дозволений авторизованим користувачам через create_booking.
  Функція визначає user_id через auth.uid(), бере ціну з rooms і перевіряє дати.
- Прямі INSERT/UPDATE/DELETE для браузера заборонені; перегляд bookings захищений RLS власника.
- room_availability повертає тільки room_id та зайняті дати, без імен гостей і user_id.
- Обмеження bookings_no_overlap захищає від одночасних перетинів бронювань.
- Повтор запиту з тим самим ID повертає вже створений запис.
- Онлайн-оплата демонстраційна. Для справжньої оплати знадобиться платіжний провайдер і серверне підтвердження.
- На GitHub Pages зміни з'являться після звичного commit/push і завершення публікації GitHub Pages.

Перевірено локально: синтаксис JavaScript; сценарії з імітацією відповідей Supabase
(збереження, помилка мережі, повтор запиту, зайняті дати, зміна акаунта, демооплата);
посилання Sign in у хедері та відкриття auth.html у браузері.
Міграцію в реальній базі потрібно виконати вручну; реальне збереження після міграції
слід перевірити кроками вище у своєму акаунті.
